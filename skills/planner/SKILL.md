# planner

ユーザーの1日の予定を、打ち合わせで決めて日次プランナーに書き込むスキル。

予定は CLI（`node ${CLAUDE_SKILL_DIR}/tools/cli.ts`）で読み書きする。CLI と画面は同じデータファイル（既定 `~/.planner/store.json`）を使うので、書き込むと開いている画面（http://localhost:5173）にもすぐ反映される。データファイルを直接編集しない（版の管理と画面への反映が CLI 経由でしか働かないため）。

## 今の状況

!`node ${CLAUDE_SKILL_DIR}/tools/cli.ts brief 2>&1 || true`

時刻・空き時間・持ち越し候補は上を基準にする。会話が長くなったら `cli.ts brief` で取り直す。

## 計画の打ち合わせ

次の順で進める。チェックリストを写して進み具合を追う。

```
- [ ] 1. 対象の日と、その日に使える時間（空き時間）を確かめる
- [ ] 2. 材料を集める（ユーザーの文章、指定されたファイル、持ち越し候補、必要なら作業フォルダ）
- [ ] 3. やることを洗い出し、15分単位で見積もる
- [ ] 4. 「今日やり切ること」を1文で決め、空き時間に並べた案を出す
- [ ] 5. ユーザーと調整する（質問は一度に2〜3個まで）
- [ ] 6. 合意したら plan を --dry-run で確かめてから書き込む
- [ ] 7. 書き込んだ結果を短く伝える
```

1. 対象の日は、言われなければ今日。今日なら今の時刻より後の空き時間だけを使う。
2. 材料は読むだけで、勝手に書き換えない。探す場所と見るべき点は [references/planning.md](references/planning.md) にある。ユーザーが材料を示さず「探して」と言ったときだけ、作業フォルダや git を探索する。
3. 見積もりは15分単位。2時間を超える作業は分けて間に休憩を入れる。同じ種類の作業には既存の予定と同じタイトルを使う（色と月の集計がタイトル単位のため）。
4. 案は表で示す（時刻・予定・見積もり・理由）。空き時間に収まらない分は「今日はやらないこと」として分けて見せ、詰め込まない。余白を1〜2割残す。
5. 見積もりや締め切りに自信がない所だけを尋ねる。ユーザーが「そのまま入れて」と言ったら確認を省いてよい。
6. 書き込みは下の「予定の書き込み」の手順で行う。既存の予定を消す（`replace`）ときは、消える予定を見せて了承を得てから。
7. 結果は「何件入れたか・今日やり切ること・画面の URL」程度にまとめる。

## 予定の書き込み

まとめて入れるときは、計画の JSON を標準入力で渡し、`--dry-run` で確かめてから同じ内容で適用する。

```bash
node ${CLAUDE_SKILL_DIR}/tools/cli.ts plan today --file - --dry-run <<'EOF'
{
  "activities": [
    { "title": "設計レビュー", "start": "09:30", "end": "10:30", "memo": "論点: API の命名" },
    { "title": "資料作成", "start": "10:45", "end": "12:15" },
    { "title": "朝会", "start": "09:00", "end": "09:15", "repeat": "平日" }
  ]
}
EOF
```

問題がなければ、`--dry-run` を外して同じ JSON で実行する。

- `--dry-run` の `warnings`（時間の重なり、時間帯の外）を読み、意図しないものがあれば計画を直してからやり直す。誤り（終了が開始より前など）があると何も書かずに終了コード 1 で止まるので、示された件を直す。
- 時刻は24時間の `HH:MM`。1日は AM 6:00〜翌 AM 6:00 で、`00:00`〜`05:59` はその日の深夜（翌朝）として扱う。
- `"replace": true`（または `--replace`）で、その日の予定を入れ替える。実績を記録した予定と繰り返し予定は残る。
- `repeat` は `月水`、`平日`、`毎日`、`1,3` のように書く。繰り返しはその日以降の同じ曜日に出る。

## 個別の操作

| したいこと | コマンド |
|---|---|
| 予定を見る | `cli.ts show <date>`（期間は `--to <date>`） |
| 1件足す | `cli.ts add <date> --title T --start HH:MM --end HH:MM [--memo M] [--repeat 曜日]` |
| 直す | `cli.ts update <date> <id> [--title] [--memo] [--start] [--end]` |
| 消す | `cli.ts remove <date> <id>`（繰り返しごとは `--series`） |
| 繰り返しを変える | `cli.ts repeat <date> <id> 月水`（やめるときは `none`） |
| 実績を記録する | `cli.ts actual <date> <id> --start --end [--status done\|partial\|skipped] [--shift]` |
| 時間帯・状態 | `cli.ts range <date> --start --end` / `cli.ts status <date> planned` |

`<date>` は `today` `tomorrow` `yesterday` `+2` `2026-11-20`。`<id>` は `show` や `brief` の id（先頭4文字以上でよい）。出力は JSON。全コマンドと出力の形は [references/cli.md](references/cli.md)。

消す・入れ替えるなど元に戻せない操作は、ユーザーが頼んだ予定だけに行い、繰り返しごと消すときは確かめてから。

## 振り返り

1日の終わりや翌朝に「振り返り」と言われたら:

1. `cli.ts show <date>` で予定を出し、各予定の実際の開始・終了と、できたか（完了・一部・未実施）を尋ねる。
2. `cli.ts actual` で記録する。予定より延びて後ろがずれたと言われたら `--shift` を付ける。
3. 記録が済んだら `cli.ts status <date> reviewed`。
4. 差分の傾向（見積もりが甘かった作業など）と、完了しなかった予定の持ち越し先を短く提案する。持ち越しを入れるのは了承を得てから。

## 画面を開く

ユーザーが画面で見たいと言ったら、開発サーバーをバックグラウンドで起動して URL を伝える。初回だけ依存関係を入れる。

```bash
npm --prefix ${CLAUDE_SKILL_DIR}/tools install   # 初回のみ
npm --prefix ${CLAUDE_SKILL_DIR}/tools run dev    # http://localhost:5173
```

データの置き場所、別の場所で使うときの設定、フックの仕組み、うまく動かないときの確かめ方は [references/setup.md](references/setup.md)。
